# ABILITILE — 能力を持ったブロックのパズル

絵柄が能力を表すパズル。ブロックを押すとその絵柄の効果が発動し、能力はブロックに
付いて一緒に動く。使ったブロック自身は動かない。盤面を目標の柄に揃えるとクリア。

## 遊び方

初めて「はじめる」を押したときだけ、決まった盤 5 面の**チュートリアル**で押す・能力が動く・長押し・組み合わせ・ヒントを覚える
（1 面 1 行。★・クリア回数・広告の回数には数えない。スキップできる。遊んだ記録がある人には自動では出さない。
メニューの「遊び方」と遊び方のシートの「チュートリアルをもう一度」から、いつでも）。

- **押す** … 絵柄の効果が順方向に 1 回
- **長押し**（右クリックでも可）… 逆方向に 1 回。回転のブロックで意味を持つ
- 盤の端はつながっていない。効果の及ぶマスが 1 つでも盤の外に出る位置では使えない
- 盤の下に **ヒント**（次に押すマスが点滅）、**解説**（順に自動で揃う。止めて
  1 手ずつ進める・戻すこともできる）、**再生成**（使うブロックも目標の柄も選び直す）
- 同じ絵柄どうしは入れ替え可能。並びが目標の柄と一致すればクリア
- ホームの一覧は **盤の大きさ × 難しさ**（3×3 は練習、4×4〜8×8 に やさしい／ふつう／むずかしい）。
  難しさは、完成形から混ぜる手数と使うブロックの種類数をまとめて上げたもの（表は script.js の `STAGE_TABLE`）。
  盤は完成形から決めた手数だけ動かして作るので、答えはほぼその手数で、大きい盤でも長くならない
- クリアすると、盤が出た時点で分かっている最短（混ぜた手順の逆と、探索で見つけた手順の短いほう）の手数と比べて **★** がつく。
  最短以下なら ★★★、その 1.5 倍（切り上げ）以内なら ★★、それより多ければ ★。
  ヒントを使うと最大 ★★。「解説」で揃えた盤と、最短を求められなかった盤には ★ がつかない

ホームの一番上の **今日の 1 問** は、端末の日付から決まる 5×5・ふつう（10 手・4 種）の盤で、同じ日は誰でも同じ盤になる。
ブロックは 13 種すべてから選ばれる（無料版でも完全版のブロックを試せる）。自分で揃えると日ごとの記録（★・手数）と
連続日数がカードに出て、**結果を共有** で目標の柄の絵文字と手数を送れる（答えの手順は出ない）。ステージのクリア数には数えない。

盤面の設定は **大きさ（3〜8）と難しさ** を選ぶ。**カスタム** を入れると、盤を長方形にでき、使うブロックも 13 種から自分で選べる
（難しさは、長い辺に近い大きさの手数を借りる）。
辺は 3〜10 から 2 つ選ぶだけで、長いほうが横になる（縦長だとスマホの画面に収まらないため）。
ヒントと「揃える」は長方形でもそのまま働く。

右上のハンバーガー（ホームでも出る）は **遊び方 / ブロック / 設定** の 3 つに分かれている。設定では
**絵柄**（ブロックの描き方）を 6 通り — 具体的なほうから点図・升目・結線・標識・単形・直線 —
から選べる。選ぶとその場で切り替わり、盤面は動かない。効果音の入切もここにある。

## 広告の口（iOS 版だけ）

`rewards.js` は広告の判定と、iOS 版（`~/GitHub/tof/ios/abilitile/native/native.js`）とのつなぎ口だけを持つ。広告そのものは Web 版に入らない。
自分で揃えるたびに回数（`glyphshift.adClears`）を数えて `abilitile:clear`（detail: `{ count, due, daily }`）を送る。`due` は通算 6 回目から 3 回に 1 回。
ごほうび広告の権利は `Entitlement.grantTicket()`（盤を始めると使い切り、ホームに戻ると消える。`isFull()` は変えない）。

## アプリとして入れる（PWA）

Chrome のアドレスバーの「アプリをインストール」から、アプリとして入れられる。
入れたあとは通信が無くても遊べる（Service Worker が一式を持っている）。

画面の右の欄（スマホでは盤の下）にある **アプリにする** からも入れられる。iPhone / Mac の Safari では
「ホーム画面に追加」の手順が出る。すでに入れてあるときや入れられないブラウザでは、このボタンは出ない。
隣の **共有** は共有シートを開く（使えない環境ではリンクをコピーする）。どちらも `webapp-kit/` の仕組み。

`manifest.webmanifest` と `sw.js` がその一式。Chrome の条件（HTTPS・manifest・
192 と 512 のアイコン・単独表示・fetch を持つ Service Worker）を満たしてある。

`sw.js` の取り方は **まず通信、駄目なら箱**。配信し直したぶんは次に開いたときに必ず
反映され、通信が無いときは箱の中身で遊べる。`VERSION` は箱を作り直すためだけのもので、
上げ忘れても新しい中身は届く。

以前は「まず箱」にしていたが、新しい版を配るのに `VERSION` の手上げが要り、
上げ忘れると古い一式が配られ続けた（実際に 3 回続けて上げ忘れて、更新が止まった）。
更新の合図を人の手に委ねない形にしてある。

## 開発

手元で動かす場合も `index.html` をブラウザで開くだけ。ビルドも依存もない。

ただし Service Worker は `file://` では動かないので、オフライン動作まで確かめるときは
ローカルのサーバで開く（例: `python3 -m http.server` → http://localhost:8000/ ）。

テストは Node で走らせる。

```
node tools/runtests.js               # すべて
node tools/runtests.js counter glyph  # 名前に含むものだけ
```

### 計測

```
node tools/bench.js <幅>x<高さ> <ブロック数> <盤面数> [予算ms] [最初のSEED]
node tools/bench.js <一辺>      <ブロック数> <盤面数> [予算ms] [最初のSEED]

node tools/bench.js 6    4 10 3000   # 6×6
node tools/bench.js 4x8  3 10 3000   # 横4×縦8
```

1 マスあたりの時間に上限があるため結果は実行ごとに揺れる。前後を比べるときは
同じ SEED で複数の盤面を回し、平均と手法の内訳の両方を見ること。

## 無料と完全版

App Store 版（Capacitor）だけ、無料版と完全版（¥500・買い切り）に分かれる。Web 版は今までどおり全部遊べる。
鍵は `entitlement.js` の `Entitlement` が判定する（`locksActive()` は iOS アプリの中だけ true。
localhost では確かめ用に `?locks=1`、完全版にするには `&full=1`）。

- 無料: ブロックは swapLR・swapUD・swapD1・swapD2・crossCW・diagCW・none の 7 種、盤は 3×3（練習）・4×4・5×5 のすべて・6×6 の「やさしい」
- 完全版: 13 種すべて、6×6 の「ふつう」「むずかしい」・7×7・8×8、カスタム盤、広告なし
- `Entitlement.stageOpen(一辺, 難しさ 0〜2)` が判定する
- 鍵つきのステージは一覧で暗くして「完全版」の札を付け、押すと案内を出す。購入そのもの（StoreKit）はまだ
- 完全版かどうかの置き場は `readFull()` の 1 か所だけ（仮。購入の実装でネイティブ側に差し替える）

## データ

localStorage（キーは `glyphshift.` で始まる）。`glyphshift.full` は完全版かどうか（`1`。仮。購入の実装で置き換える）。`glyphshift.stages` は `{"5d1": {seed, clears, goal, pool, perfect}}`（キーは「一辺d難しさ 0〜2」。旧仕様の `5x3` は読まずに残る）。`pool` は goal を作ったブロックの範囲（無料なら `free`、無ければ全部）。
`perfect` は ★★★ を取った回数で、正方形・カスタムでない盤だけ数える（無ければ 0 として読む）。
`glyphshift.tutorial` は最初のチュートリアルを終えた・飛ばした印（`done`）。あれば次からは自動では出さない。
`glyphshift.daily` は今日の 1 問の記録 `{"2026-10-29": {moves, stars, hint}}`（日付は端末のローカル時刻）。自分で揃えたときだけ、その日のよいほう（★が多い、同じなら手数が少ない）を残し、直近 60 日だけ持つ。

## 設計の要点

**状態は「絵柄の並び」** … タイルの個体は区別しない。目標も手の効果も絵柄の位置しか
見ないため、これで過不足がなく、状態空間が階乗から多項係数に落ちる（4×4 2 色なら
20,922,789,888,000 通り → 12,870 通り）。厳密な最短手順が出せるのはこのおかげ。

**手は単位コストの無向辺** … 「順方向に 1 回」「逆方向に 1 回」の 2 種類。使ったブロックは
動かないので逆の手は必ず打てる。よって単位コストの無向グラフ上の最短経路問題になる。

**盤は手数を決めて作る** … 完成形から、ちょうど n 手だけランダムに動かす（`scrambleBoard`）。
直前の手と同じマス、通った盤面（絵柄の並び）に戻る手は選ばないので、答えまでの手数はほぼ n。
混ぜた手順の逆がそのまま「n 手の答え」で、ヒントの最初の手順になり、★の基準（par）の上限になる。
盤が出たあとは裏で探索を続け（予算を倍にしながら）、短い手順が見つかれば差し替える。
一様に混ぜ切る方法（`mixBoard`。打てる手から選ぶだけでは居座りやすいので、次数の比で採択する
Metropolis 補正を入れて定常分布を一様にしてある）は、今のアプリでは使わず、テストと計測用に残している。

**目標の柄は対称性から作る** … 1 マスの色を「何かの場 f(i,j) の値 ÷ 色数 の余り」と決める。
場が持つ対称性がそのまま柄の対称性になる。距離で塗れば軸 4 本＋90°回転の全対称が自動で
手に入り、対称な場どうしを足しても対称は保たれ、基本領域だけ塗って折り返せば必ずその
対称を持つ。盤のサイズと色数で作れる柄は 1〜29 種あり、同じ配置になるものは 1 つにまとめる。

**絵柄は能力の構造から描く** … `glyphs.js` は能力の一覧を持たない。`cells(0, 0)` が返す
「中身をどのマスへ送るか」だけを見て、動くマス・行き先・対の本数・系統（入れ替え／回転／
半回転）を読み取り、6 通りの描き方に流す。能力を足しても描画側は直さなくてよい。

**色はブロックごとに固定** … 遊び込むと色でブロックを見分けられるように。色相を保ったまま
彩度と明度を探索で調整し、いちばん近い 2 色の知覚的な差（CIELAB の ΔE）を 12 色で 35 まで
広げてある。ブロックを足すときも既存の色は動かさない（色で覚えている人のために）。
空いている色相・彩度・明度から、既存すべてから最も離れる組み合わせだけを探す。
